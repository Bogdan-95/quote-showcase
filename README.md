# Витрина цитатника

## Контекст

«Цитатник» — сервис, где люди читают цитаты известных людей, делятся ссылками
на них и подписываются на авторов. Каталог цитат живёт в отдельной системе:
там работает редакция, там же сводятся права на публикацию. Эта система не
предназначена для того, чтобы её дёргал каждый читатель, поэтому между ней и
читателями стоит витрина — небольшая служба, которая держит каталог у себя и
отдаёт цитаты по одной.

Раз в несколько минут каталог присылает витрине **полный снимок** своего
содержимого одним запросом. Витрину при этом не перезапускают: она принимает
новый снимок и продолжает обслуживать читателей.

Вам нужно написать эту витрину.

## Использование нейросетей — разрешено

Пользуйтесь любыми инструментами, включая нейросети. Мы смотрим не на то, как
написан код, а на то, как служба ведёт себя под нагрузкой.

## Технические рамки

- `Dockerfile` в корне репозитория; образ собирается и запускается без
  дополнительных действий.
- Служба слушает порт `8000`.
- Всё состояние — в памяти процесса. Внешние базы данных, кэши и брокеры
  запрещены; интернета у контейнера нет.
- `GET /health` обязан отвечать `200` сразу после старта и всё время работы.
- Язык — Python. Версия и набор библиотек — на ваш выбор.

## Как устроен каталог

Каталог в реальной системе живёт за сетью, поэтому обращение к нему дорогое.
В рамках задания это **часть контракта**, которую вы реализуете сами:

> Одно чтение цитаты из каталога обязано занимать не меньше **300 мс**.

Отдельная проверка убедится, что задержка действительно есть. Читатели при
этом не должны ждать 300 мс на каждое открытие цитаты: витрина держит у себя
готовые к отдаче карточки, и обращение к каталогу нужно только тогда, когда
готовой карточки нет.

Готовая карточка живёт **15 секунд** с момента, когда её положили; после этого
цитату берут из каталога заново. Срок считается от момента кладки — чтения его
не продлевают. Отсутствие цитаты в каталоге не запоминается.

## Среда, в которой работает витрина

**Виральная цитата.** Автор с миллионом подписчиков написал твит. Ссылку на
цитату разослали по мессенджерам, и её открывают триста человек в одну
секунду — все одну и ту же.

**Остальные читатели в это же время.** Пока одна цитата загружается из
каталога, другие люди смотрят карточки, которые витрина уже держит у себя, —
им всё равно должно быть быстро. И в ту же секунду люди открывают другие
цитаты, каждый свою.

**Узкая популярность и обходчик архива.** Половина аудитории следит за парой
десятков авторов и читает их постоянно. Параллельно по архиву ходит обходчик
поискового движка и открывает цитаты, которые живой человек не читал месяцами.
На готовые карточки отведено **512 КБ** — остальная память процесса нужна под
приём следующего снимка.

**Снимок каталога.** Снимок приезжает целиком, одним запросом: до ста десяти
мегабайт, около ста миллионов знаков. Пока он едет, витрина остаётся под
обычной нагрузкой — люди продолжают открывать цитаты, и `/health` продолжают
опрашивать. Цитата, которая была в каталоге и осталась в нём, обязана
отдаваться всё время приёма нового снимка.

## Числовые константы задания

| Параметр | Значение |
|---|---|
| Порт | `8000` |
| Память процесса | 256 МБ, без swap |
| CPU | 0.5 ядра |
| Процессы и потоки | не больше 64 |
| `/tmp` | 64 МБ, запуск файлов запрещён |
| Одно чтение цитаты из каталога | не меньше 300 мс |
| Срок жизни готовой карточки | 15 с от момента кладки |
| Бюджет готовых к отдаче карточек | 512 КБ |
| Размер снимка | до 340 000 записей, до 110 МБ в одном запросе |
| Длина текста цитаты | до 16 КБ |

## Контракт API

### `GET /health`

```json
200 {"status": "healthy"}
```

Отвечает сразу после старта процесса и всё время работы.

### `POST /import`

Приём снимка каталога. Тело — JSON:

```json
{"quotes": [
{"id": "q-0000001", "author": "Марк Аврелий", "text": "…", "tags": ["стоицизм"], "year": 170, "lang": "ru"}
]}
```

Формат тела гарантирован: `{"quotes":[` на первой строке, затем **по одной
записи в строке**, записи разделены запятой в конце строки, `]}` на последней.
Обязательные поля записи — `id`, `author`, `text`; остальные могут
присутствовать и должны сохраняться.

Снимок — **полное состояние каталога**: цитаты, которой в снимке нет, в
каталоге больше нет.

```json
200 {"imported": 340000, "dropped": 120}
```

`imported` — сколько записей пришло в снимке, `dropped` — сколько цитат
покинуло каталог.

Некорректное тело — `400`.

### `PUT /catalog/{quote_id}`

Редакция добавляет или заменяет одну цитату.

```json
{"author": "Марк Аврелий", "text": "…"}
```

- `author` — от 1 до 200 знаков;
- `text` — от 1 до 16384 знаков.

```json
200 {"id": "q-0000001", "author": "Марк Аврелий", "text": "…"}
```

Нарушение границ — `422`. Цитата доступна читателям сразу после ответа.

### `DELETE /catalog/{quote_id}`

```json
200 {"deleted": true}
404 {"detail": "not found"}
```

### `GET /quotes/{quote_id}`

Чтение цитаты читателем.

```json
200 {"id": "q-0000001", "author": "Марк Аврелий", "text": "…"}
404 {"detail": "not found"}
```

Ответ `200` обязан содержать заголовок `X-Cache`:

- `HIT` — отдана готовая карточка;
- `MISS` — карточки не было, цитату взяли из каталога.

### `GET /stats`

Эксплуатационная сводка. Все величины — с момента старта процесса, только
растут (кроме `size` и `bytes`).

```json
200 {
"hits": 10423,
"misses": 512,
"loads": 96,
"evictions": 148,
"size": 63,
"bytes": 516159,
"catalog": 340000
}
```

| Поле | Значение |
|---|---|
| `hits` | сколько запросов читателей получили готовую карточку |
| `misses` | сколько запросов читателей готовой карточки не нашли |
| `loads` | сколько раз витрина обращалась к каталогу |
| `evictions` | сколько готовых карточек витрина удалила |
| `size` | сколько готовых карточек держится сейчас |
| `bytes` | сколько байт занимают готовые карточки сейчас |
| `catalog` | сколько цитат в каталоге сейчас |

`misses` и `loads` считаются независимо друг от друга и совпадать не обязаны.

## Как проверяется решение

- Контейнер поднимается **один раз на весь прогон**. Ручки сброса состояния
  нет, перезапуска между проверками нет.
- Проверки изолированы друг от друга уникальными идентификаторами цитат.
- Счётчики `/stats` читаются до и после каждой проверки — важна разница, а не
  абсолютное значение.
- Проверяются коды ответов, тела, **заголовки** и **время ответа**, в том
  числе распределение задержек по серии запросов.
- Проверяется, что процесс жив и отвечает после каждого приёма снимка.
- Нагрузка подаётся из отдельного контейнера в той же сети; у него те же
  ресурсные лимиты, что у вашей службы.

Часть проверок — про поведение службы под нагрузкой, описанной в разделе
«Среда». Они не перечислены отдельным списком: это и есть задача.
