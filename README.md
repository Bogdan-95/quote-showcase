# Quote Showcase

Асинхронная in-memory витрина цитат на FastAPI. Сервис принимает полный снимок каталога, обслуживает чтение отдельных цитат и использует ограниченный LRU-кэш с TTL.

Проект исследует три инженерные задачи: потоковый импорт большого набора данных, конкурентные запросы к одной записи и ограничение потребления памяти.

## Возможности

- FastAPI REST API.
- Потоковый приём JSON-снимка построчного формата.
- Хранение каталога в виде сериализованных JSON bytes.
- LRU-кэш с TTL 15 секунд и лимитом 512 KiB.
- Single Flight: конкурентные запросы одной цитаты используют одну загрузку из каталога.
- Метрики запросов, загрузок и вытеснения.
- Docker-образ и отдельный сценарий нагрузочной проверки.

## Архитектура

```text
Catalog snapshot
      |
      v
Streaming import -----> In-memory catalog (id -> JSON bytes)
                                  |
                                  v
Reader -----> LRU cache <---- Single Flight lock per quote
                  |
                  v
             JSON response
```

### Single Flight

При промахе кэша запрос получает lock для своего `quote_id` и повторно проверяет кэш после получения lock. Первый запрос загружает запись, остальные используют уже сохранённый результат.

Важно различать три метрики:

- `misses` — количество запросов, у которых первоначальная проверка кэша не нашла запись. При конкурентном всплеске одна и та же цитата может дать много misses.
- `loads` — количество фактических обращений к каталогу после повторной проверки под lock.
- `hits` — количество ответов, обслуженных из кэша, включая запросы, которые дождались Single Flight.

Поэтому для 300 одновременных запросов одной отсутствующей в кэше цитаты ожидается один фактический load, а не обязательно один первоначальный miss.

## API

| Метод | Endpoint | Назначение |
|---|---|---|
| GET | `/health` | Проверка доступности |
| GET | `/stats` | Счётчики сервиса |
| POST | `/import` | Приём полного снимка каталога |
| PUT | `/catalog/{id}` | Добавление или замена цитаты |
| DELETE | `/catalog/{id}` | Удаление цитаты |
| GET | `/quotes/{id}` | Чтение цитаты, заголовок `X-Cache` |

### Пример

```bash
curl http://localhost:8000/health
curl http://localhost:8000/stats
curl http://localhost:8000/quotes/q-0001
```

## Запуск локально

Требуется Python 3.12+.

```bash
git clone https://github.com/Bogdan-95/quote-showcase.git
cd quote-showcase

python -m venv .venv
source .venv/bin/activate  # Windows: .venv\\Scripts\\activate

pip install -r requirements.txt
uvicorn main:app --host 127.0.0.1 --port 8000
```

## Тестирование

Установить зависимости разработки:

```bash
pip install -r requirements-dev.txt
pytest -q
ruff check app tests main.py --select E,F --ignore E501
```

Unit-тесты проверяют LRU/TTL, потоковый импорт и поведение API без внешнего каталога.

## Нагрузочные проверки

`test_load.py` — отдельный ручной сценарий проверки TTL, большого импорта и чтения под нагрузкой. Сначала запусти сервис, затем:

```bash
python test_load.py
```

Скрипт использует `httpx` и `psutil`. Нагрузочные результаты из `SOLUTION.md` — исторические замеры автора, а не гарантия производительности на другом оборудовании.

## Ограничения

- Каталог находится в памяти процесса и теряется после перезапуска.
- Проект рассчитан на один процесс приложения; несколько Uvicorn workers будут иметь независимые каталоги и кэши.
- Импорт использует гарантированный построчный формат снимка, а не произвольный JSON с переносами внутри записей.
- Сначала весь снимок проверяется во временном файле, затем каталог обновляется in-place. Это защищает старый каталог от частично разобранного невалидного тела, но во время короткой фазы применения разные ключи могут отражать старую и новую версии снимка.
- `test_load.py` — ручной нагрузочный скрипт, не unit-тест и не CI benchmark.
- Для публичного развёртывания нужны аутентификация источника импорта, rate limiting, мониторинг и политика восстановления после потери памяти.
